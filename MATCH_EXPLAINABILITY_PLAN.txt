1. THE THREE DISPLAYED "MATCH" NUMBERS (decomposable, unchanged)
--------------------------------------------------------------------------------
A) Target-role match  Dashboard ScoreRing  `analysis.match_score`
       source: backend/app/matching.py  `job_match_score(student, role)`
       formula: per required skill, equal weight 1.0; credit = 1.0 if
       student level >= required level else student/required (partial),
       0 if missing.  pct = round(earned/total*100, 1). Violent-simple,
       rows already live behind `categorize()` as strong/gap/missing.

B) Recommended-role match  recommendation cards' rings  `recommendations[].match_score`
       source: backend/app/recommendations.py  `recommend()` (lines ~343-396)
       formula: per required skill w = specificity(key) * (essential ? 1.0 :
       OPTIONAL_WEIGHT); credit = w * (1.0 if level >= required else
       level/required); verified multiply by (1.0 + VERIFIED_BOOST 0.05);
       ESCO discovery credit = specificity(dkey)*1.0 (boost template same);
       pct = round(min(100.0, earned_w/total_w*100), 1). Note the clamp: an
       ESCO discovery skill can push earned_w above total_w, so the min(100)
       clamp is a REAL labelled line, never hidden.

C) Job match  jobs feed cards  `jobs[].match_pct`
       source: backend/app/jobs.py  `_score_job()` (lines 1228-1400) +
       `_apply()` caps (2812-2815) + `_rerank_score` (1067, ordering only)
       formula steps (each cap is its OWN labelled line):
         relevance = min(56, hits*14)
         [+24 if family-title hit]                 cap 70
         [+6 if family hit and relevance>=40]      cap 80
         (no family hit)<= max(rel, min(60, 18+len(title_hits)*18))
         [+min(8, len(minor_hits)*2)]              cap 90
         [+min(6, len(verified_hits)*3)]           cap 94
         [+min(4, max(0, 4-int(listed_days_ago)))] cap 96   (only if fresh)
         exp  = 0 / 20 / 12 from job_seniority vs student_seniority
         loc  = _LOCATION_SCORES tier (city/country/country_remote/global_remote/
                market/unknown/different) via _location_score()
         score = max(0, min(100, int(round(relevance+exp+loc))))
         [student_seniority==0 and job_sen>1]  score = min(score, 15)
         [_apply]                                score = min(score, 40)
                 only when loc_tier=="different"

All three formulas are deterministic given (profile, role, job record); the
goal is to re-run the same arithmetic with the same inputs and emit every
intermediate as a labelled component/adjustment line that sums EXACTLY to the
number already on screen. If recomputation ever disagrees, raise a 500 with a
clear "cannot decompose" message and log it (guide: stop + document, never
present a wrong sum). Test parity batteries below enforce this forever.

3.1 NEW FILE backend/app/match_explain.py (coach for all three breakdowns)
  Constants: TARGET_ROLE_MATCH_FORMULA="target-role-match-v1",
             ROLE_MATCH_FORMULA="role-match-v1",
             JOB_MATCH_FORMULA="job-match-v1".
  Evidence vocabulary: "verified" | "self_reported" | "esco_discovery" | "none".

  target_role_match_breakdown(student):
    - reads student.target_role; None -> raise MatchExplainError(404) honest.
    - reuses matching.categorize() rows; recomputes per-skill credit with the
      SAME loop shape as matching.job_match_score (single source: it calls
      matching.effective_skill_level under the hood via categorize).
    - PARITY: recomputed_total must equal matching.job_match_score(student,
      target_role); on mismatch raise (endpoint -> 500 + logged conflict).
    - payload: {formula, version, as_of (UTC ISO), role_data_version =
      target_role.source_version or "local", role_title, company, skill_gaps:
      each {skill_id, skill_name, required_level, student_level|null,
      evidence, status strong|gap|missing, contribution_points (credit in
      points, max 1.0), required_flag}, total_points, max_points, raw_percent
      (unrounded), displayed_percent, rounding_adjustment (displayed - raw,
      rounded to 1dp; labelled "+0.00 from rounding" etc),
      evidence_precedence ("verified > self_reported"), missing_data summary,
      next_action (worst rows first: missing then gap; suggests the single
      next skill to practice/verify). }

  role_match_breakdown(student, role_id=None, external_id=None):
    - runs recommendations.recommend(student) with the student's profile;
      finds the candidate by role_id or external_id. Found -> use the
      per-requirement detail produced by the refactored _score_candidate
      (see 3.2) -> guaranteed identical pct.
    - NOT found in current recommendations -> raise MatchExplainError(404)
      with detail "not in the student's current recommendations".
    - payload: {formula, version, as_of, role_data_version = cand.source_version
      or "local", source (catalog|company|esco), title, company,
      requirements: each {name, required_level, student_level|null, evidence,
      essential, weight, level_factor|null, credit, is_discovery, verified},
      total_weight, earned_weight, raw_unclamped_percent, clamp_to_100_adjustment
      (only when earned>total), rounding_adjustment, displayed_percent,
      matched_skills, missing_key_skills, verified_matches, next_action,
      evidence_precedence, missing_data}.

  job_match_breakdown: implemented in jobs.py (3.4) and wrapped here with the
   profile context (student skills/role/country/location/requisites/market,
   mirroring api_recent_jobs), the cache lookup, and the exact-input parity
   guard. 404 honest for unknown fingerprint; 500 on parity mismatch.

   Shared honest-rules module-level docstring + a tiny _fmt helper so every
   adjustment line prints the same way ("<label> <signed-value> pts").

  MatchExplainError(status_code, message) for clean endpoint mapping.

6. EXACT-TOTAL INVARIANT (the heart of the phase)
--------------------------------------------------------------------------------
For every displayed number N shown today:
  N == sum(existing components) + sum(labelled adjustment lines)
The adjustment lines are present ONLY where the existing math applies a
transformation (rounding, min-100 clamp, 0/100 clamp, 15-cap, 40-cap, freshness
cap). Their labels make the transform legible ("int rounding +0.2 pts";
"seniority cap -N pts (entry-level vs senior title)"; "relocation cap -N pts
(different market)"). If recomputing N from the components ever fails to equal
the value the app already displays, the code raises -> 500 + a documented
conflict log line. Silent score changes are forbidden; this phase changes no
score, only adds the breakdown view.
