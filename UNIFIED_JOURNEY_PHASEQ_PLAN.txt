-------------------------------------------------------------------------------
GOAL (Phase Q spec, as read from the handoff)
-------------------------------------------------------------------------------
"Unified learning-to-application journey." A student should be able to follow a
single, honest spine from "build evidence" → "close gaps" → "find matched jobs"
→ "apply + track" without the loop dead-ending or hopping to a generic page.
Required properties:
  * A journey readout derived ONLY from real payloads (target-role analysis,
    verified/self-reported skills, scenario library, Phase-K tracker counts) —
    never a fabricated readiness number.
  * When the student is career-ready (all required skills strong & verified),
    the journey hands off to the real match feed + application tracker instead
    of showing a no-action dead-end.
  * "Prepare for this job" compares the JOB LISTING'S OWN required_skills
    (real field from jobs.py normalization) against the student's profile; a
    deep link to Learning/Practice/Assessments exists ONLY when the skill
    resolves to a real DB skill id. Unresolvable names are honestly labeled
    "no SkillBridge path yet", never fabricated as gaps.
  * A tracker row that reaches stage `interview` offers the EXISTING Mock
    Interview (practice only). Tracker rows carry a shareable-evidence token
    only when the student has already enabled share_public — never auto-publishes.
  * Hard NEVERs: never invent skills/jobs/readiness; never auto-apply or auto-
    move a tracker stage; never claim an interview/application outcome; never
    show an employer-facing artifact the student didn't share.

DECISIONS (additive, honest, backward-compatible)
-------------------------------------------------------------------------------
D1. "UNIFIED" = DASHBOARD-EMBEDDED JOURNEY SPINE, NOT A NEW SECTION. Rationale:
    Phase N deliberately kept the board on the Dashboard; a new "My Journey"
    Section would fork the same content across two pages and add a full nav +
    breadcrumb + regression surface for marginal benefit. The spine recomposes
    the EXISTING cards on the Dashboard into one readable sequence, which is
    the "unified journey" the handoff asks for. (Alternative — a dedicated
    Section consolidating gap map + board + tracker — is recorded in
    OUT OF-SLICE as a follow-up candidate, not built now.)
D2. JOURNEY PHASE IS DERIVED, CLIENT-SIDE, NEARLY-ZERO-CHANGE. A pure
    presentational header computes an honest stage from data the Dashboard
    already has:
      - no target / no analysis     → "1 · Build evidence" (CTA → Skills hub)
      - analysis, gaps remain       → "2 · Close the gaps" (Next Step CTA)
      - gaps closed, gaps verified  → "3 · Ready for opportunities" (→ jobs)
      - stage reached interview etc → "4 · Find, apply & track" (→ tracker)
    Each of the five steps (Learn / Verify / Practice / Find / Track) shows a
    real status chip + CTA to the real section. Phase labels are human copy
    over derived booleans — the RULES are: nothing new computed, no readiness
    percentage invented (match ring stays the only number).
D3. CAREER-READY HAND-OFF (fixes the P5 dead-end). When nextStep returns
    action:null ("All requirements met — career ready"), the journey step card +
    Recommended-Next card render a "Find your match & apply" Go that scrolls to
    the JobsCard (+) and highlights the tracker. Honest: it hands off to the
    real feed; it never claims any hiring outcome. The Go is a scroll/focus
    action, not a new route.
D4. GROUNDED "PREPARE FOR THIS JOB" (replaces the generic Skills hub hop).
    New read-only backend endpoint (cheap, uses the CURRENT feed row, no
    recompute, no cache-key fork):
      GET /api/students/{id}/jobs/recent/{fingerprint}/prepare
      (owner-gated _own_student; 404 when the fingerprint is not in the
      student's current feed — jobs.peek_feed_job, same locate semantics as
      the Phase K save endpoint main.py:2933).
    Response:
      { job: {title, company, location_label, match_pct, apply_url,
               listing_status, provider},
        skills: [{name,        // job.required_skills real name
                  skill_id,    // REAL DB id via normalise_name resolution,
                               // or null when no skills row exists
                  status,      // verified | self_reported | gap | no_path
                  student_level?, verified_at?}] }
    `status` derives: name matches a verified skill → verified; else matches a
    self-reported skill → self_reported; else resolves to a skills row → gap
    (deep-linkable); else → no_path (skill_id null, honest "no SkillBridge
    learning path for this exact skill yet" — deep link falls back to the
    Skills hub). The UI is a dialog (role=dialog, Escape/backdrop, focus
    return): per-skill row with evidence badge + a "Review in Learning" /
    "Practice" / "Verify" deep link ONLY when skill_id is real; the job's own
    Apply link (live rows only, target=_blank rel=noopener) + a "share your
    verified-skill profile" chip when share_public is on. NEVER fabricates a
    missing skill or a skill_id.
D5. INTERVIEW-READY PREP (bridge tracker → Mock Interview). In JobTrackerPanel,
    a row whose stage is `interview` gains "Prepare with a mock interview →
    " calling the EXISTING AppContext.startInterview() with applyCopilot job
    context (job title/url). Practice only, never auto-starts, never sends
    anything outside the app, reuses the existing interview session.
D6. SHAREABLE-EVIDENCE CHIP ON TRACKED JOBS. A tracker row shows a "Share your
    verified profile" affordance ONLY when student.share_public is 1, linking
    to the existing /p/{id} public profile (+) or #skill-{n} for a verified
    skill belonging to the row. Never auto-publishes; no new public data.
D7. TINY BACKEND SURFACE. Exactly ONE new endpoint (D4) + models helper
    (prepare_job_view or equivalent) + tests. Everything else is frontend
    composition over existing endpoints. Migration: NONE (read-only).
D8. SECOND CONSUMER SAFETY (checked, not changed): SkillsRolesPage role-drawer
    "Available jobs" keeps reading api.recentJobs; MatchBreakdown and the Phase
    K tracker routes are untouched; JobsCard row actions change only the
    Prepare button (D4). The Phase N checker's negative guards remain true.

  no skills row renders "no SkillBridge path yet", never a fake gap or fake id.
- Deep links exist ONLY when skill_id is a real DB id.

- Interview prep reuses the existing Mock Interview (practice), never auto-

  never auto-marks applied (Phase N rule preserved).
- The shareable-evidence chip appears only when share_public=1; it only links
  the student's own existing public profile.
- All additions additive: SkillsRolesPage drawer, MatchBreakdown, Phase K
  routes, feed health, and Phase N checkers stay green unchanged.
