3. Fixes made
--------------------------------------------------------------------------------
  a. App.tsx LearningPage wiring: replaced a legacy search stub
     (onNavigate={(s)=>setSection(s)}) that silently dropped the deep-path
     focus object; LearningPage now receives the real focus-aware navigate.
  b. navigate() roots the breadcrumb back-context only at a hub (Skills &
     Roles or Dashboard), killing the learning<->scenarios navigation loop.
  c. AssessmentsPage focus race: the incoming skill id is captured at mount
     (focusSkillIdRef) and resolved in a second effect once allSkills load, so
     "Verify a Skill" keeps + highlights the right item even with a slow fetch.
  d. SkillsRolesPage drawer: replaced firstGapSkill (which misread name-presence
     as "have" and left Start/Verify dead for catalog roles) with level-aware
     resolution straight from the live gap-analysis ids (never fabricated).
  e. Scenario results: "Review {skill} in Learning" / "Take the Assessment" now
     deep-link only when the weakest competency maps to a real DB skill
     (e.g. suspicious-login -> Incident Response id 32); otherwise the CTA is
     honestly hidden and the follow-up message + Practice again remain.
  f. Phase 6 CSS: .scn-card-top flex-wrap + .scn-card min-width:0, and
     .cov-row/.cov-label/.cov-tally responsive rules <=640px eliminated the
     only remaining horizontal overflows (scenario cards, company dashboard).
  g. Fixed a "Scenarios" section name that silently remapped the
     ("skills_roles") CTA to the Dashboard instead of the Skills & Roles page.

5. Setup instructions
--------------------------------------------------------------------------------
MAC (this machine)
  - Backend:   cd backend && ../.venv/bin/python -m uvicorn app.main:app
                 --host 0.0.0.0 --port 8000     (must run from backend/)
  - Frontend:  cd frontend && npm ci && npm run build && npm run dev
  - Browser regression harness:
                 cd scripts/browser-regression && npm ci && node phase6-regression.js
                 (uses the system Google Chrome; server must be running)
  - One-click: ./start.sh   (also included: scripts/start.mjs, verify.sh)

WINDOWS
  - The bundled Mac dependencies (.venv binaries; frontend .bin launchers) may
    NOT run on Windows. Create a fresh virtual environment and install fresh:
        cd backend
        py -3 -m venv ../.venv-win        (or .venv)
        ../.venv-win/Scripts/activate
        python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
      (requirements are declared in backend/requirements*.txt; reinstall with
       pip install -r requirements.txt if the venv is rebuilt)
    Frontend:
        cd frontend && npm ci --force && npm run build && npm run dev
    Fingerprint the Mac .venv instead of copying it; the packages are pinned the
    same way, so a fresh install is deterministic.
  - One-click: start.bat   /   start.ps1
  - Docker (cross-platform): Dockerfile + docker-compose.yml /
    docker-compose.prod.yml; see DOCKER_README.md and DOCKER_CHECKLIST.md.

BOTH
  - Restore real secrets: the .env shipped in this archive is already in place;
    .env.example documents the expected shape for a fresh install.
  - Server keeps running at http://localhost:8000 for inspection.
