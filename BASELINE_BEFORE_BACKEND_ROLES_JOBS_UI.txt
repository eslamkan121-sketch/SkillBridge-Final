6. ROLE AND JOB REQUEST/DATA FLOWS
--------------------------------------------------------------------------------
ROLES
- Source roles: company-owned (roles.company_id), reference catalog
  (roles.is_reference=1, source='company', owning catalog company
  "SkillBridge Talent Catalog"), and ESCO occupations imported via
  select_esco_role (source='esco', external_id=ESCO URI).
- Catalog endpoint: /api/roles/catalog serves list_catalog_roles().
- ESCO: backend/app/escoe.py queries the public ESCO search/resource API
  (https://ec.europa.eu/esco/api/...), scores occupations, and market_occupations
  functions. Imported role skills are attached via role_skills with
  required_level default 'Intermediate'. No ESCO version pinning/refresh service
  yet (Phase E target).
- Matching: matching.py analyze_student / matching.categorize produce skill gaps;
  recommendations.py recommend() builds the role pool (local + ESCO) with
  specificity, confidence, warnings; matching score drives the dashboard
  readiness and job reranking. Explainable matching (Phase J) does NOT yet exist
  beyond raw score; there is no per-skill contribution breakdown exposed.
- Saved roles: saved_roles(student_id,role_id) idempotent, ownership-gated.

JOBS
- Feed: GET /api/jobs/recent (limit, location, country, market). Requires the
  student's CV (self-reported skills) before returning a matched feed.
- Providers (12, in priority order): JSearch, LinkedIn, Google Jobs, Adzuna,
  USAJobs, Remotive, Jobicy, Arbeitnow, RemoteOK, Jooble, Himalayas,
  Get on Board. Keyless boards always attempted; keyed ones need env keys;
  RapidAPI LinkedIn/Google are host-gated (never guessed).
- Pipeline: fetch_all (parallel, short timeouts, per-provider status) -> merge
  (normalize + dedupe by URL and by normalized title+company+location) ->
  rerank (skills/experience/board + career-family penalty) -> cache (TTL
  JOBS_CACHE_TTL_SECONDS default 900s) -> build_result with source live|empty|
  unavailable + provider report.
- Health: provider_status() secret-free; cache hits/misses; per-provider
  cooldown after 429/403/timeout (JOBS_COOLDOWN_SECONDS).
- Known gaps for this upgrade: cache key is built from role/skills/country/
  location/limit/market but multi-user/page/filter isolation and LRU bounds are
  NOT proven (Phase G); link-quality/dead-link verification is minimal (blocklist
  + expiry flags) (Phase H); honest per-request health vocabulary is partial
  (Phase I); saved jobs / application tracker do not exist (Phase K).
