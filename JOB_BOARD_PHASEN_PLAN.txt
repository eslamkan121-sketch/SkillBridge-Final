------------------------------------------------------------------------------
Redesign the current job feed around the proven backend contracts without
removing any provider or obscuring partial failure. Features required: search +
filters for data ACTUALLY supplied (location/market, provider, work type,
seniority, freshness, saved/applied state, minimum match); active-filter chips +
one clear-all; paginated results; a job card with title, company, location,
provenance, freshness, match summary, saved/application state, expiry/link

missing skills, learning and scenarios; report-dead-link action; provider-health
drawer with honest categories and no secrets; cached/stale/offline banners;
mobile filter drawer; keyboard-accessible controls. NEVER display unknown fields
as facts; never auto-open external links or mark a student applied; preserve
safe URL handling; test every state; browser smoke with MOCKED partial-provider
failure.

DECISIONS (additive, honest, backward-compatible)
------------------------------------------------------------------------------
D1. FILTERS/PAGINATION = CLIENT-SIDE. Backend search/filter/page would fork the
    Phase-G cache key per term (provider storms) and is out of the proven
    contract. The board requests limit=16 (server clamp, one bounded cache row;
    additive to the contract) and filters/paginates the SURFACED rows client-
    side (8/page). Every filter option is derived ONLY from fields actually
    present in the rows; work_type/seniority values equal to 'unknown'/'not
    specified'/'' are NOT offered as options and rendered as absent (never shown
    as facts). freshness buckets computed from real listed_days_ago/published_
    date/fetched_at. saved/applied filter from the Phase-K tracker stages map.
    minimum match = threshold on match_pct. Search box = client-side token
    overlap on title/company/location/provider/skills/tags (a filter, not a
    fact).
D2. JOB CARD = NEW SEMANTICS, SAME CONTRACT. Reserved: title, company,
    location(city·country), provider (provenance badge), freshness (posted Nd
    ago / published), match summary (badge + j.match_reason), saved/application
    state (Save toggle + stage badge when tracked), expiry/link status
    (listing_status/expired/link-unavailable chips + link_state when relevant).
    description_excerpt shown only when non-empty (real field). Salary never
    shown (no honest source). External open stays explicit, target=_blank
    rel=noopener noreferrer, never auto-opened; expired/flagged rows have no
    click-through link (title text, no URL), matching today's safe behavior.
D3. EXPANDABLE MATCH EXPLANATION = reuse MatchBreakdown kind="job" (Phase J)
    per row when j.fingerprint — no new endpoint, no recompute.
D4. "PREPARE FOR THIS JOB" = grounded the the dashboard's OWN gap machinery.
    onClick: set applyCopilot job context (existing) then reuse nextStep
    (analysis + scenario library + target title) -> go(section,
    {skillId?, roleTitle}) — identical to the Recommended Next Step, so the
    deep link lands on real missing-skills/learning/scenarios with a real DB
    skillId when analysis exists, else go('skills') (the journey hub). No
    per-job skill gap is ever fabricated.
D5. REPORT-DEAD-LINK = NEW append-only backend (migration 0008_job_link_reports
    + owner-gated POST /api/students/{id}/jobs/recent/{fingerprint}/report-dead
    -link + list read). A report is an AUDIT record (fingerprint, url, title,
    provider, reported_by, reported_at), never a verdict: _VERIFIED_DEAD_JOB_URLS
    stays curated-only, the link stays safely unopened, and the row shows a
    "Link reported — we will verify it." note (in-session state + re-derived on
    mount). Idempotent (one open report per student+fingerprint). No secrets.
D6. PROVIDER-HEALTH DRAWER = new presentational component; opens from the feed
    header; fetches api.jobsHealth() (new typed helper over /api/config/
    demo-mode reading the jobs key) once on first open (fired ref). Groups the
    canonical health codes into honest categories (Healthy / Empty success /
    Throttled (rate-limited) / Auth needed / Unreachable / Timed out / Malformed
    / Disabled / Unconfigured / Unknown), each provider's reason verbatim, plus
    cache {hits,misses,avg_fetch_ms}, providers_available, last_build_at.
    Accessible dialog (role=dialog, Escape, close button, backdrop).
D7. BANNERS = read data.status+source (extend RecentJobsResponse types): cached
    copy banner, stale_fallback ("refreshing in the background"), unavailable
    (existing honesty), offline (network-error state already captured), no-cv
    (existing CTA).
D8. MOBILE FILTER DRAWER + A11Y: ≥641px inline filter bars; ≤640px all filters
    move behind a "Filters (n)" trigger opening a filter drawer (reuse the
    established overlay pattern), Escape/backdrop close + focus return. All
    controls are real <button>/<label><select> with aria-labels; result-count
    live region announces filter/pagination changes.
D9. SECOND CONSUMER SAFETY: SkillsRolesPage role-drawer "Available jobs" keeps
    reading api.recentJobs fields (fingerprint, listing_status, provider,
    listed_days_ago, match_pct, title, company, location, url) — untouched
    (verified in the Phase N checker by positive-guard assertions).

HONESTY INVARIANTS (locked by checker + tests)
------------------------------------------------------------------------------
- No salary/market figures anywhere on the board (no honest source).
- work_type/seniority 'unknown'/'not specified'/'' are absent, not facts.
- Filters expose ONLY values present in the current rows.
- status='cached'/'stale_fallback'/'fresh'/'unavailable' + source fully
  surfaced in banners; nothing is ever presented as live unless it is.
- Saved state = Phase-K tracker; stages change ONLY via explicit tracker PATCH
  (each stage change is an audit row) — the board never auto-marks applied.
- External links: live rows only, target=_blank rel=noopener noreferrer,
  user-initiated; expired/link-unavailable rows have no URL.
- A dead-link report is an audit record, never an auto-blocklist write.
- Compare/match numbers are reused from backend payloads, never recomputed.

OUT OF-SLICE (documented): no new provider; no server-side search/filter/page
(kept client-side); dead-link verification stays manual/curated; the jobs
experience stays embedded in the Dashboard (no separate jobs Section in Phase N);
